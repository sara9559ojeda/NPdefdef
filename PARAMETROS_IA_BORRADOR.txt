BORRADOR — PARÁMETROS EXISTENTES PARA ANÁLISIS POSTERIOR
Proyecto: NeuroPhobia_FUNCIONAL

Alcance y cautela
Este inventario describe solo datos que aparecen en el código actual. No implementa IA ni propone/inventa variables de captura. Un campo “podría consumirse” indica compatibilidad técnica potencial como dato de entrada/etiqueta, no que exista modelo, entrenamiento, evaluación clínica o interpretación validada.

Conteo: 17 campos de dominio serializados en SessionReport (5) y LevelMetrics (12). Los wrappers HTTP agregan campos de transporte y se enumeran después de la tabla, no forman parte de los 17.

Estructura JSON

SessionReport:
- sessionId: string
- phobiaGrade: integer
- totalDuration: number (float)
- levelMetrics: array de LevelMetrics
- timestamp: string ISO UTC

LevelMetrics:
- level: integer
- gazeTimeOnSpider: number
- avoidanceAttempts: integer
- headMovementFrequency: number
- proximityMin: number
- taskCompletions: array de string
- breathingActivations: integer
- levelPassed: boolean
- sessionDuration: number
- levelAttempts: integer
- handWithdrawals: integer
- handContactDuration: number

SessionManager serializa el reporte completo con `JsonUtility.ToJson(report, true)` a `Application.persistentDataPath/session_<SessionId>.json` al final de sesión.

Wrappers de transporte existentes:
- POST `/api/session/start`: `{ sessionId, phobiaGrade, timestamp }`
- POST `/api/session/metrics`: `{ sessionId, level, metrics }`
- POST `/api/session/end`: `{ sessionId, fullReport }`
- GET `/api/session/command/{sessionId}`; respuesta esperada `{ action }`.
- Base URL por defecto: `http://localhost:8000` (`FastAPIClient.baseUrl`). No se encontró implementación FastAPI/backend en el inventario Unity.

Comandos adaptativos actuales
`AdaptiveCommandPoller` pregunta cada 5 s si existe SessionId. Solo contempla `pause` y `resume`. `pause` establece BREATHING durante 15 s; `resume` vuelve a PLAYING. Ante error HTTP se devuelve `none`. No se hallaron comandos para cambiar PhobiaGrade, velocidades, rutas u otros parámetros.

A. Datos que YA EXISTEN
Los 17 campos de la tabla y la lógica que intenta llenarlos. La calidad/actualización real varía: el código incluye varios métodos de registro cuyo consumidor no se encontró, y ciertas métricas se asignan solo al completar.

B. Datos PREPARADOS para backend
Los tres POST, GET de comando y los payloads anteriores existen en FastAPIClient. SessionManager invoca POST start/metrics/end si encuentra el componente FastAPIClient. El menú/escena y configuración deben verificarse en runtime; que el endpoint esté en código no demuestra que el servicio esté instalado, disponible o accesible desde Quest. `localhost` requiere particular atención en dispositivo.

C. Datos que NO existen en este esquema/código inspeccionado
No aparece salida, nombre, versión o confianza de un modelo de IA; inferencia/predicción; frecuencia cardíaca, EEG u otros sensores fisiológicos; registro crudo de trayectoria o mirada con timestamps; calibración ocular; edad/demografía; etiquetas diagnósticas; consentimiento; versión de protocolo; ni persistencia histórica/almacenamiento backend implementado aquí. No deben tratarse como existentes ni inferirse de métricas actuales.
