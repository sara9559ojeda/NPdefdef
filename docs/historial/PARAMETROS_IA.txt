PARÁMETROS UNITY PARA INTEGRACIÓN POSTERIOR
Proyecto: NeuroPhobia_FUNCIONAL

Alcance y cautela
Este inventario describe solo datos que aparecen en el código actual. No implementa IA ni propone/inventa variables de captura. Un campo “podría consumirse” indica compatibilidad técnica potencial como dato de entrada/etiqueta, no que exista modelo, entrenamiento, evaluación clínica o interpretación validada.

Conteo: 17 campos de dominio serializados en SessionReport (5) y LevelMetrics (12). Los wrappers HTTP agregan campos de transporte y se enumeran después de la tabla, no forman parte de los 17.

Estructura JSON

SessionReport:
- sessionId: string
- phobiaGrade: integer
- totalDuration: number (float)
- levelMetrics: array de LevelMetrics
- timestamp: string ISO UTC

LevelMetrics:
- level: integer
- gazeTimeOnSpider: number
- avoidanceAttempts: integer
- headMovementFrequency: number
- proximityMin: number
- taskCompletions: array de string
- breathingActivations: integer
- levelPassed: boolean
- sessionDuration: number
- levelAttempts: integer
- handWithdrawals: integer
- handContactDuration: number

SessionManager serializa el reporte completo con `JsonUtility.ToJson(report, true)` a `Application.persistentDataPath/session_<SessionId>.json` al final de sesión.

Transporte al backend: contrato API v1.1.0 (rama feature/unity-contrato-v1.1, 2026-11-05)
Fuente del contrato: `NP_Back/docs/api/CONTRATO_API_v1.md`, sección 6. Todas las rutas van bajo `<servidor>/api/v1`.
- Emparejamiento (inicio de sesión del visor, BPMN): `POST /device/pair` `{ code, deviceModel, appVersion }` -> `{ deviceId, deviceToken }`. El token se guarda en `persistentDataPath/device_credentials.json` y viaja como `Authorization: Bearer`.
- Contexto en el Refugio (solo en MainMenu, nunca durante la exposición): `GET /device/context` -> `allowedStartLevel`, `phobiaGrade`. Copia local en `device_context.json`; sin red se usa la copia y, si no hay, Nivel1.
- Ajustar grado de fobia (BPMN): `PUT /device/phobia-grade` `{ phobiaGrade }` al pulsar el grado; el grado también viaja en `session_start`.
- Registros: `POST /device/records` con sobres `{ recordId, type, schemaVersion: 1, sessionId, payload }`, tipos `session_start`, `level_record` y `session_end` (`DeviceRecordMapper`).
- Cerrar sesión del visor: `POST /device/unpair` (botón en MIS DATOS; no se permite mientras queden registros sin enviar).
- Se retiró `GET /api/session/command/{sessionId}` (D13): `AdaptiveCommandPoller` queda inerte y se desactiva al arrancar.

Correspondencia LevelMetrics -> level_record (payload)
- level -> level; número de intento por nivel y sesión -> attempt (empieza en 1); `DeviceRecordMapper.LevelDefinitionVersion` -> levelDefinitionVersion.
- levelPassed -> criterionMet; outcome (nuevo campo de LevelMetrics) -> outcome: completed, criterion_not_met, safe_exit (salida de emergencia) o abandoned (volver al menú desde la pausa). Vacío = completed si levelPassed, si no criterion_not_met.
- sessionDuration -> permanenceSeconds; endedAt = momento del registro, startedAt = endedAt - permanenceSeconds.
- proximityMin -> minDistanceM (`null` cuando vale -1, sin estímulo muestreado).
- gazeTimeOnSpider -> gaze.onStimulusSeconds; gaze.coneDeg = 1 (rayo central de MetricsCollector, no es un cono); gaze.meanAngleDeg = null (no se mide).
- avoidanceAttempts -> avoidanceCount. suds = [] (la app todavía no pregunta SUDS). events = level_start, safe_exit si aplica, level_end.
- extra: taskCompletions, breathingActivations, headMovementMean (= headMovementFrequency), handContactSeconds, handWithdrawals, levelAttempts.
- session_end: endReason completed (Nivel5 superado), user_finished, safe_exit (salida de emergencia) o app_closed (OnApplicationQuit); levelReached = nivel más alto registrado; totalDurationSeconds = totalDuration.

Bandeja de salida (D12)
Cada sobre se escribe en `persistentDataPath/outbox/<deviceId>/` antes de enviarse y se borra solo con 201 stored o 200 duplicate. 409/422/400/413/403 -> `outbox_quarantine/`. 401 -> se conserva, se borra el token y la app pide un código nuevo. 429, 5xx, 503 STORAGE_UNAVAILABLE o sin red -> reintento en orden con espera creciente (2 s, 4 s, … hasta 5 min) o la indicada en Retry-After.
Los sobres quedan ligados al emparejamiento con el que se crearon: nunca se envían con el token de otro paciente. Las sesiones sin visor vinculado (solo en Editor o builds de desarrollo) se marcan como `testSession` y se quedan en `outbox/sin_vincular/`.
Mensajes visibles: el error de envío (BPMN «¿Almacena datos? no») aparece en el menú principal y en el resumen de sesión; el resumen muestra «Retroalimentación guardada» cuando el `session_end` vuelve con `feedback.status = saved`.
- URL del servidor por defecto: `http://localhost:8000` (`FastAPIClient.baseUrl`, objeto con SessionManager en MainMenu); se le añade `/api/v1` si no lo trae.

Cómo apuntar a un FastAPI en la LAN
`FastAPIClient.Awake` resuelve la URL en este orden (la primera válida gana; debe empezar por http:// o https://, se quita la barra final):
1. Archivo `backend_url.txt` en `Application.persistentDataPath` con una sola línea, p. ej. `http://192.168.1.50:8000` (con o sin `/api/v1`).
   - Quest: `adb push backend_url.txt /sdcard/Android/data/com.neurophobia.app/files/backend_url.txt` (después reiniciar la app).
   - PC/Editor: `%USERPROFILE%\AppData\LocalLow\NeuroPhobia\NeuroPhobia\backend_url.txt` (companyName y productName actuales).
2. PlayerPrefs `NeuroPhobia.BackendUrl` (se puede fijar en runtime con `FastAPIClient.SetBaseUrl(url)`, que la guarda y la aplica).
3. Valor serializado `baseUrl` del componente (Inspector).
Al arrancar se registra en consola `NeuroPhobia: backend en <url>`.
Requisitos de red: el servidor debe escuchar en todas las interfaces (`uvicorn main:app --host 0.0.0.0 --port 8000`), el firewall de Windows debe permitir el puerto 8000 y la Quest debe estar en la misma red. `localhost` en la Quest apunta a la propia Quest, no al PC.
`ProjectSettings > Player > insecureHttpOption = 2` (Allow downloads over HTTP: Always allowed) permite `http://` en cualquier build; con 0 Android bloquea HTTP en claro.

Comandos adaptativos (retirados)
El contrato API v1 retira la consulta de comandos durante la exposición (D13). `AdaptiveCommandPoller` sigue en las escenas solo para no dejar «Missing Script»: se desactiva en Awake y no hace peticiones. La recomendación del backend llega por `GET /device/context` en el Refugio.

A. Datos que YA EXISTEN
Los 17 campos de la tabla y la lógica que intenta llenarlos. La calidad/actualización real varía: el código incluye varios métodos de registro cuyo consumidor no se encontró, y ciertas métricas se asignan solo al completar.

B. Datos ENVIADOS al backend
SessionManager llama a FastAPIClient (PostSessionStart, PostLevelMetrics, PostSessionEnd), que convierte los datos en sobres del contrato v1.1.0 y los envía desde la bandeja de salida. El backend guarda métricas, análisis y retroalimentación en una sola transacción al recibir `session_end`. Verificado el 2026-11-05 contra NP_Back con PostgreSQL efímero (ver registro de cambios). Falta probarlo desde el Editor y desde la Quest contra un servidor en la LAN.

C. Datos que NO existen en este esquema/código inspeccionado
No aparece salida, nombre, versión o confianza de un modelo de IA; inferencia/predicción; frecuencia cardíaca, EEG u otros sensores fisiológicos; registro crudo de trayectoria o mirada con timestamps; calibración ocular; edad/demografía; etiquetas diagnósticas; consentimiento; versión de protocolo; ni persistencia histórica/almacenamiento backend implementado aquí. No deben tratarse como existentes ni inferirse de métricas actuales.

Nota de interfaz: GlobalSessionUI registra el nivel completado o interrumpido con MetricsCollector.BuildMetrics(passed); SessionManager evita duplicar el mismo nivel. El resumen utiliza GetReport(). La asignación grado -> nivel inicial queda pendiente de definición; todo grado inicia en Nivel1.

Progresión de niveles (vigente desde 2026-10-28)
Nivel1 -> Nivel2 -> Nivel3 -> Nivel4 -> Nivel5. El Nivel2 nuevo (antes `Nivel2Nuevo.unity`) es ahora `Assets/Scenes/Nivel2.unity`; el parque anterior quedó en `Nivel2_Parque_Anterior.unity`, fuera de Build Settings. El botón Siguiente de `GlobalSessionUI` está activo en Nivel1 a Nivel4 (`NextLevelOf`); Nivel5 cierra la sesión con `TaskManager` y `GlobalSessionUI.ShowSessionSummary`. El MainMenu carga `allowedStartLevel` del backend (Nivel1 si no hay contexto).

Un MetricsCollector activo por nivel (escenas)
- Nivel1: `LevelManagers` (sin cambios).
- Nivel3: `Nivel3_AutoSetup` (el que referencian Level3AdaptiveCalmV2 y Level3ProgressControllerV2); se eliminó el de `LevelManagers`, que no tenía araña.
- Nivel4: `LevelManagers` activado (MetricsCollector level 4, LevelBootstrap y AdaptiveCommandPoller); su `spider` apunta a `NP_Spider_Level4`, la araña del flujo NPLevel4Controller. `Nivel4_AutoSetup` (flujo antiguo con su propio collector) sigue inactivo.
- Nivel5: `MetricsCollector_Nivel5` (usado por TaskManager y Level5SpawnManager, que le pasa las arañas instanciadas). `LevelManagers` activado sin su MetricsCollector, para conservar solo el poller y LevelBootstrap. `NPLevel5Controller` (flujo fábrica/orbes) deshabilitado: ya no activa `L5_Orb_1`.
`GlobalSessionUI.Capture` usa `FindFirstObjectByType<MetricsCollector>()`; con un único collector activo por escena el resultado es determinista. Si no hay collector, el LevelMetrics de respaldo usa `proximityMin = -1`.

- Escenas Nivel3, Nivel4 y Nivel5: collectors y poller como se describe arriba.
